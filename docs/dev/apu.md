# APU（サウンド）

**結論**: 4 チャンネルを遅延評価で動かし、48kHz・16bit ステレオでリングバッファに書く。MenuetOS 版はそれを syscall 117 のダブルバッファ（format 0）に渡す。
CPU 命令ごとに APU を進めると TCG 上の負荷が大きいため、サウンドレジスタへのアクセス時・DIV リセット時・フレーム終了時にまとめて追いつかせる。
48kHz は MenuetOS の全ドライバーが必ず対応する format 0 で、リサンプリングを省ける。

## 構成（`src/core/apu.inc`）

- `gb_tick` は `apu_pending` に T サイクルを足すだけ。`apu_sync` が「次のサンプル」と「次の DIV bit 12 の立ち下がり」の近い方ずつ進める
- フレームシーケンサーは DIV bit 12 の立ち下がり（512Hz）で進む。DIV への書き込みで bit 12 が落ちる場合も 1 ステップ進む
- 出力: `apu_ring`（16384 フレーム、下位ワード L・上位ワード R）、`apu_wpos` は書いた総フレーム数。読み位置は各フロントエンドが持つ
- ミックス: 各チャンネル 0〜15 を NR51 で左右に振り、NR50 で (音量+1) 倍、`APU_GAIN` 倍した後、DC を除くハイパスフィルター（時定数 512 サンプル）を通す
- 矩形波・波形チャンネルは経過した段数を割り算 1 回で進める（高音でもループしない）。ノイズは LFSR を 1 段ずつ回す
- サンプルは点サンプリング（帯域制限なし）

## MenuetOS での再生（`src/menuetboy.asm`）

- 起動時に 117/1（確保）→ 117/7・117/8（format 0、バッファ 16384 バイト = 4096 フレーム ≒ 85ms）→ 無音を 2 面渡して 117/3（再生開始）
- メインループ毎回 117/4 で再生中のバッファを見て、前回埋めた面に移っていたらもう一方を `apu_ring` から埋める。遅延は 1〜2 バッファ分（85〜170ms）
- データが足りない分は直前のフレームを繰り返し、画面の `underrun frames` に数える（起動直後の 1 面分は必ず数える）。3 バッファ分以上たまったら古い分を捨てる
- 起動フロッピーの `config.mnt` は既定で音声無効・Intel HDA ドライバーなので、`scripts/build.sh` が AC97 に有効化して ISO を作る（UTM の音声デバイスは AC97）

## テスト

`scripts/test.sh` に含まれる:

- Blargg dmg_sound 01〜08・11（`tests/roms/snd-*.gb`）。結果はシリアルではなくカートリッジ RAM（A001 の DE B0 61 と A000 の結果コード）で判定する
- 440Hz トーン: `tests/sound_tone.py` が ch2 を鳴らす ROM を作り、ハーネスが書き出した音声のゼロクロスから周波数と振幅を確認する

| 却下した案 | 却下理由 |
|---|---|
| 命令ごとに APU を進める | 1 命令ごとにチャンネル処理が走り、TCG 上で数倍の負荷になる |
| 44.1kHz など別のレートで生成 | ドライバー側の対応が保証されない。format 0 の 48kHz で足りる |
| 帯域制限合成（BLEP など） | 実装量に対して改善が小さい。まず鳴らすことを優先 |

## やらないこと

- dmg_sound 09・10・12（ch3 再生中の波形 RAM アクセス）。DMG 固有のサイクル単位の挙動で、ゲームへの影響が小さい
- CGB 固有の挙動、PCM12/PCM34 レジスタ
