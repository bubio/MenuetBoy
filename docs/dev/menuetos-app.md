# MenuetOS 64bit アプリの形式

**結論**: アプリは fasm の `format binary`（`use64`、`org 0`）で作るフラットバイナリで、先頭に `MENUET64` ヘッダーを置く。
システムコールは `rax` に機能番号を入れて `int 0x60`（または `syscall`）。
エミュレーターに必要な画面転送・キー入力・ファイル読み込み・時間待ちは、すべて 64bit システムコールで揃う。

出典: 公式 [syscalls.txt](https://www.menuetos.net/syscalls.txt)（v1.61.00）、[e64.asm](https://www.menuetos.net/e64.asm)、ISO 内 `SOURCE/M64/APP64/*.ASM`

## ヘッダー

```asm
use64
    org   0x0

    db    'MENUET64'              ; Header identifier
    dq    0x01                    ; Version
    dq    START                   ; Start of code
    dq    image_end               ; Size of image
    dq    0x100000                ; Memory for app
    dq    0xffff0                 ; Rsp
    dq    0x00                    ; Prm
    dq    0x00                    ; Icon
```

アプリはアドレス 0 から確保メモリ（上の例では 1MB）の範囲で動く。ROM・VRAM バッファ・スタックはすべてこの中に収める。

## 呼び出し規約

- 機能番号: `rax`、引数: `rbx, rcx, rdx, r8, r9, r10`、戻り値: `rax`（一部 `rbx`）
- `int 0x60` が基本。`syscall` は高速だが `rcx, r11, r14` を壊し、引数の `rcx/r11` を `rbp/r15` で渡す
- 座標・サイズは「開始 shl 32 + サイズ」の形で 1 レジスタにまとめる
- サンプルには 32bit 互換の `int 0x40`（`eax` に機能番号）も混在するが、新規コードは `int 0x60` に統一する

## エミュレーターで使うシステムコール

| 番号 | 機能 | 用途 | 要点 |
|---|---|---|---|
| 0 | ウィンドウ定義・描画 | 画面枠 | `r8=1`、`r9` にタイトル文字列 |
| 7 | 画像表示 | LCD 160x144 の転送 | `rdx` に RRGGBB 配列、`r10=3`（3 バイト/画素）、`r9=0x1000000`（透過なし） |
| 10 / 11 | イベント待ち / 確認 | メインループ | 戻り値ビット 0: 再描画、1: キー、2: ボタン |
| 223 | タイムアウト付きイベント待ち (µs) | フレーム同期 | 待ち時間はスケジューラー（1000Hz）の刻み。TCG では ms タイマーと同じく遅れるので、RTC で補正した比率で換算して渡す |
| 3 / 26 | RTC / システム情報（11: ms タイマー） | 時間計測 | ms タイマーは TCG で遅れる。RTC の秒で速さを測って補正する |
| 2 | キー取得 | ジョイパッド | `rbx` bit 0 が押下/離上（0/1）。押しっぱなしを追える |
| 17 | 押されたボタン取得 | 閉じるボタン | ID 1 が閉じる |
| 58 | ファイル | ROM・セーブ | `rbx=0` 読み込み（512 バイト単位、`rbx` にファイルサイズ）、`1` 書き込み（既存ファイルがあると error 16 なので先に `2` で削除）、`2` 削除 |
| 512 | プロセス終了 | 終了 | |
| 117 | オーディオ | 音声 | 1 確保、7/8 形式（0 = 48kHz 16bit ステレオ）、2 バッファ転送、3 再生、4 再生中のバッファ、5 停止、255 解放。`config.mnt` での有効化が必要（[apu.md](apu.md)） |

## やらないこと

- 32bit アプリ形式（`MENUET01`、`int 0x40` のみ）への対応
- C ライブラリ（menuetlibc）経由での開発
